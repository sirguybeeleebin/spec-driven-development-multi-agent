# Агенты

Каждый AI-агент получает объект `State` и использует определённые части состояния в соответствии со своей ролью и задачей.

## Researcher

Researcher анализирует задачу, изучает интерфейсные контракты и технические ограничения проекта, исследует необходимые технические решения и формирует результаты исследования.

Для формирования пользовательского промпта Researcher читает следующие данные:

1. **`state.task.goal`** — цель задачи, определяющая, какой результат необходимо получить и какие требования должны быть учтены.

2. **`state.task.fqns`** — список Fully Qualified Name компонентов, участвующих в задаче. Используется для определения области исследования.

3. **`state.task.interfaces`** — интерфейсные контракты. Для каждого интерфейса Researcher читает:
   - `name` — имя компонента.
   - `language` — язык программирования.
   - `description` — описание назначения и ответственности компонента.
   - `steps` — пошаговые инструкции по реализации.
   - `content` — сигнатура или исходный код компонента.

4. **`state.task.constitution`** — технические правила и ограничения проекта, которые необходимо учитывать при исследовании и выборе решений.

5. **`state.task.sequence`** — необязательное описание последовательности взаимодействия компонентов. Если присутствует, Researcher использует его для понимания взаимодействий и ожидаемого поведения системы.

Дополнительно Researcher получает список `skills`, содержащий доступные навыки:
- `skill.name` — название навыка.
- `skill.description` — описание его назначения и области применения.

Таким образом, Researcher получает контекст задачи, интерфейсные контракты, технические ограничения, последовательность взаимодействия компонентов и каталог доступных навыков.

## Implementer

Implementer получает объект `State` и отвечает за реализацию текущего интерфейса в существующей кодовой базе в соответствии с требованиями задачи, техническими ограничениями и результатами исследования.

Для формирования пользовательского промпта Implementer читает следующие данные:

1. **`state.task.goal`** — цель задачи, определяющая ожидаемый результат реализации.

2. **`state.task.fqns`** — список Fully Qualified Name компонентов. Используется для сопоставления коротких имён интерфейсов с их полными именами.

3. **`state.current_interface`** — интерфейс (`Interface`), назначенный для текущей реализации. Implementer читает:
   - `name` — имя реализуемого компонента.
   - `language` — язык программирования.
   - `description` — описание назначения и ответственности компонента.
   - `steps` — пошаговые инструкции по реализации.
   - `content` — сигнатура или исходный код компонента.

4. **`state.current_target_file`** — путь (`Path`) к файлу, в котором необходимо реализовать текущий интерфейс.

5. **`state.task.interfaces`** — полный список интерфейсов задачи. Для каждого интерфейса Implementer читает имя, язык программирования, описание, шаги реализации и содержимое. Используется для понимания связей и контрактов между компонентами задачи.

6. **`state.task.constitution`** — технические правила и ограничения проекта, обязательные при реализации.

7. **`state.task.sequence`** — необязательное описание последовательности взаимодействия компонентов. Используется для понимания ожидаемого поведения и взаимодействия реализуемого компонента с остальной системой.

8. **`state.agent_results[Agents.RESEARCHER]`** — результаты работы Researcher. Implementer использует последний результат исследования (`response`) в качестве дополнительного технического контекста для реализации.

Дополнительно Implementer получает список `skills`, содержащий доступные навыки:
- `skill.name` — название навыка.
- `skill.description` — описание его назначения и области применения.

Таким образом, Implementer получает контекст задачи, текущий интерфейс и целевой файл реализации, контракты остальных компонентов, технические ограничения проекта, последовательность взаимодействия компонентов и результаты исследования.

## Tester

Tester получает объект `State` и отвечает за проверку реализации на соответствие критериям приёмки. Анализирует текущий сценарий Gherkin, интерфейсные контракты и последовательность взаимодействия компонентов, формирует и выполняет тесты.

Для формирования пользовательского промпта Tester читает следующие данные:

1. **`state.current_gherkin`** — сценарий приёмки (`Gherkin`), назначенный для текущего тестирования. Tester читает:
   - `name` — название сценария.
   - `fqn` — Fully Qualified Name компонента, поведение которого проверяется.
   - `test_fqn` — Fully Qualified Name тестовой функции.
   - `given` — предусловия сценария.
   - `when` — действия, выполняемые в сценарии.
   - `then` — ожидаемые результаты выполнения.

2. **`state.task.interfaces`** — список интерфейсов задачи. Для каждого интерфейса Tester читает:
   - `name` — имя компонента.
   - `language` — язык программирования.
   - `description` — описание назначения и ответственности компонента.
   - `steps` — пошаговые инструкции по реализации.
   - `content` — сигнатура или исходный код компонента.

3. **`state.task.sequence`** — необязательное описание последовательности взаимодействия компонентов. Используется для понимания взаимодействий, которые необходимо учитывать при тестировании.

Дополнительно Tester получает список `skills`, содержащий доступные навыки:
- `skill.name` — название навыка.
- `skill.description` — описание его назначения и области применения.

Таким образом, Tester получает текущий сценарий приёмки, контракты всех компонентов задачи, последовательность взаимодействия компонентов и каталог доступных навыков.

## Fixer

Fixer получает объект `State` и отвечает за исправление ошибок, обнаруженных при тестировании. Анализирует текущий сценарий приёмки и результаты работы Tester, определяет причины ошибок и корректирует реализацию.

Для формирования пользовательского промпта Fixer читает следующие данные:

1. **`state.current_gherkin`** — сценарий приёмки (`Gherkin`), в рамках которого обнаружены ошибки. Fixer читает:
   - `name` — название сценария.
   - `fqn` — Fully Qualified Name компонента, поведение которого проверяется.
   - `test_fqn` — Fully Qualified Name тестовой функции.
   - `given` — предусловия сценария.
   - `when` — действия, выполняемые в сценарии.
   - `then` — ожидаемые результаты выполнения.

2. **`state.agent_results[Agents.TESTER]`** — результаты работы Tester. Fixer использует последний результат (`response`), содержащий информацию о проведённом тестировании и обнаруженных ошибках.

Дополнительно Fixer получает список `skills`, содержащий доступные навыки:
- `skill.name` — название навыка.
- `skill.description` — описание его назначения и области применения.

Таким образом, Fixer получает сценарий приёмки, результаты тестирования и каталог доступных навыков, необходимые для анализа и исправления обнаруженных ошибок.
