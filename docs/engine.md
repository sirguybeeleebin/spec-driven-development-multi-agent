# Specification-Driven Development Multi-Agent Engine

## Структура спецификации проекта

Спецификация проекта состоит из пяти основных компонентов.

1. **Constitution (`AGENT.md`)** — содержит общие инструкции и технические ограничения проекта. Определяет технологический стек, архитектурные принципы, соглашения об именовании, правила работы с базой данных, обработки ошибок и другие требования, обязательные для всех агентов.

2. **Configuration (`AGENT.yaml`)** — содержит конфигурацию движка и AI-агентов. Определяет LLM-провайдеров, модели, параметры генерации, доступные инструменты, навыки и ограничения количества итераций.

3. **Tasks (`tasks/*.md`)** — содержит спецификации отдельных задач разработки. Каждая задача определяет идентификатор, цель, интерфейсные контракты, критерии приёмки и последовательность выполнения операций.

4. **Skills (`skills/*/SKILL.md`)** — содержит специализированные инструкции и знания для выполнения определённых типов работ. Навыки могут включать дополнительные скрипты, справочные материалы и ресурсы.

5. **Workflows (`workflows/*.md`)** — содержит описания рабочих процессов и графы зависимостей между задачами. Определяет порядок выполнения задач и зависимости между ними.

## Task

Каждая задача разработки представлена отдельным Markdown-файлом (`tasks/*.md`) и состоит из следующих разделов:

1. **Task** — идентификатор задачи (`task_id`), однозначно определяющий её в проекте.

2. **Goal** — описание цели задачи, ожидаемого результата, функциональных требований и ограничений реализации.

3. **Interfaces** — контракты компонентов, необходимых для выполнения задачи. Каждый интерфейс определяется Fully Qualified Name (FQN) и содержит:
   - Cигнатуру компонента.
   - Описание назначения и ответственности.
   - Пошаговые инструкции по реализации.
   - Описание возвращаемых значений и возможных исключений, если применимо.

4. **Sequence** — необязательное описание последовательности взаимодействия компонентов при выполнении операции. Может быть представлено в виде Mermaid Sequence Diagram.

5. **Gherkins** — сценарии приёмки, определяющие ожидаемое поведение реализуемых компонентов. Каждый сценарий содержит:
   - Название сценария.
   - FQN компонента, поведение которого проверяется.
   - Test FQN — полное имя тестовой функции.
   - Gherkin-сценарий с шагами Given, When, Then, описывающими предусловия, действие и ожидаемый результат.

## Состояние

Состояние (`State`) — объект, содержащий текущий контекст выполнения задачи и результаты работы AI-агентов. Передаётся между компонентами системы и обеспечивает доступ к данным, необходимым для реализации, тестирования и исправления ошибок.

Состоит из следующих компонентов:

1. **task** — задача (`Task`), содержащая:
   - `task_id` — уникальный идентификатор задачи (`TaskID`).
   - `goal` — описание цели задачи.
   - `fqns` — список Fully Qualified Name компонентов, участвующих в задаче.
   - `interfaces` — список интерфейсов (`Interface`), содержащих имя, язык программирования, исходный код, описание и шаги реализации.
   - `gherkins` — список сценариев приёмки (`Gherkin`), содержащих название, FQN проверяемого компонента, Test FQN и шаги Given, When, Then.
   - `constitution` — технические правила и ограничения проекта.
   - `sequence` — необязательное описание последовательности взаимодействия компонентов (`Sequence`), содержащее язык и содержимое.

2. **current_interface** — интерфейс (`Interface`), который в данный момент обрабатывается. Может отсутствовать.

3. **current_gherkin** — сценарий приёмки (`Gherkin`), который в данный момент обрабатывается. Может отсутствовать.

4. **current_target_file** — путь (`Path`) к файлу реализации текущего интерфейса. Может отсутствовать.

5. **current_target_test_file** — путь (`Path`) к файлу тестов текущего сценария. Может отсутствовать.

6. **agent_results** — словарь результатов работы AI-агентов (`AgentResult`), сгруппированных по типам агентов (`Agents`). Для каждого типа агента создаётся отдельный список результатов.
